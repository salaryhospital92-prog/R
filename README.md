## الحالة الحالية

قاعدة البيانات **منفّذة فعلياً** على المشروع `slrhxeozdadonarkclba` في **فرانكفورت
(eu-central-1)** — الأقرب للعراق — وفحوصات السلامة الـ17 نجحت كلها، وملف `.env`

### الخطوة اليدوية الوحيدة — حساب المدير
Supabase يسجّل الدخول بالبريد الإلكتروني لا باسم مستخدم، فاختر بريداً ولو داخلياً.

1. Supabase → **Authentication → Users → Add user → Create new user**
   - Email: `admin@alrifaie.com`
   - Password: كلمة السر التي تريدها
   - فعّل **Auto Confirm User** (وإلا لن يستطيع الدخول قبل تأكيد البريد)
2. **SQL Editor** ونفّذ هذا السطر كما هو — لا تحتاج نسخ أي رقم:
   ```sql
   update public.profiles p set role = 'admin'
     from auth.users u
    where u.id = p.id and u.email = 'admin@alrifaie.com';
   ```
3. للتأكد:
   ```sql
   select u.email, p.role from public.profiles p join auth.users u on u.id = p.id;
   ```

أي حساب يُنشأ لاحقاً يبدأ تلقائياً بدور `data_entry` — لا يحتاج منك شيئاً.

## الصور والمساحة

**مكان التخزين:** Supabase Storage — bucket عام اسمه `product-images`، على نفس
مشروع فرانكفورت. لا تُخزَّن الصور في قاعدة البيانات ولا في GitHub.

**مصادر الصورة الثلاثة:** الكاميرا · معرض الصور وأي ملف في الجهاز · **رابط خارجي**
(من نتائج جوجل أو عدسة جوجل) — يُجلب عبر دالة `img-proxy` على الخادم لتجاوز حجب
CORS، ثم يمرّ بنفس مسار التصغير. الوسيط لا يكتب شيئاً في التخزين، ويتطلّب جلسة
موظف، ويرفض العناوين الداخلية (SSRF).

**عدسة جوجل:** بعد حفظ صورة المنتج يفتح زر «عدسة جوجل» عنوان
`lens.google.com/uploadbyurl` بصورة المنتج المرفوعة — فتتعرّف العدسة على المنتج
وتعرض صوره الرسمية، ثم يُلصق رابط الأوضح منها في حقل الرابط.

**التصغير — الوجهتان:**
- **من لوحة الموقع:** تُصغَّر **في جهاز الموظف قبل الرفع** إلى عرض 1024px وجودة 0.8
  عبر Canvas — صورة جوال 4 ميغابايت تصير ~150 كيلوبايت (توفير ~25 ضعفاً).
- **من بوت التيليغرام:** تيليغرام نفسه يضغط الصورة قبل أن تصلنا (بحد أقصى 1280px)،
  والبوت يأخذ النسخة المضغوطة لا الأصل — القياس الفعلي: ~9 كيلوبايت للصورة.
- مسار الصورة ثابت لكل منتج (`{productId}.jpg`) مع `upsert` — تبديل الصورة **يستبدل**
  الملف ولا يترك نسخاً يتيمة، ولاحقة `?v=` تكسر ذاكرة المتصفح لتظهر الجديدة فوراً.
- حذف المنتج يحذف صورته أيضاً.
- الحصيلة: **الباقة المجانية (1 غيغابايت) تكفي ~7000 منتج بصورة لكل منتج.**

## الإشعارات عند وصول طلب

| القناة | متى تعمل | الإعداد |
|---|---|---|
| **تيليغرام** | دائماً — حتى والتطبيق مغلق | لوحة المدير ← التوصيل ← إشعار التيليغرام |
| **تنبيه داخل التطبيق** | واللوحة مفتوحة (Realtime + صوت) | زر الجرس في رأس اللوحة |

إشعار التيليغرام يُرسل من قاعدة البيانات نفسها عبر `pg_net` في trigger على
`orders`، فلا يعتمد على بقاء متصفح مفتوحاً، وفشله لا يُفشل الطلب أبداً.

## قواعد ثابتة
- **الأسعار في جدول منفصل** (`product_prices`) يقرؤه المدير وحده — لأن RLS تعمل على
  مستوى الصفوف لا الأعمدة، فموظف الإدخال لا يصله السعر من الخادم أصلاً.
  المتجر يقرأ عبر العرض `storefront_products` الذي يقدّم السعرين (جملة/مفرد) بقرار المالك.
  لإقفال أسعار الجملة لاحقاً خلف رمز: احذف `price_wholesale` من العرض وأنشئ دالة
  `wholesale_catalog(p_code text)` تتحقق من الرمز.
- **الطلب يُنشأ عبر `create_order`** التي تقرأ الأسعار من قاعدة البيانات وتحسب المجموع
  بنفسها. رابط `wa.me` يُبنى **بعد** نجاح الحفظ ومن رد الدالة، لا من السلة.
- **الكميات تتغير عبر `stock_movements` فقط** — لا تعديل مباشر على `quantity_single`.
- **المبالغ `bigint`** بالدينار العراقي، والعرض بـ `Intl.NumberFormat('ar-IQ')`.
- **الواجهة RTL** — استعمل `ms-/me-/ps-/pe-/start-/end-` لا `ml-/mr-/left-/right-`.

## النشر (بدون Vercel / Netlify / Cloudflare)

الواجهة ملفات ثابتة (HTML/CSS/JS) بعد `npm run build` — أي استضافة ملفات تكفي،
والخلفية على Supabase أصلاً. الخيارات المتاحة:

| الخيار | التكلفة | HTTPS (شرط الكاميرا) | ملاحظة |
|---|---|---|---|
| **GitHub Pages** | مجاني | ✅ تلقائي | المستودع موجود أصلاً — الأبسط |
| Render (Static Site) | مجاني | ✅ | يبني من GitHub تلقائياً |
| استضافة عادية (cPanel) | مدفوعة | حسب المزوّد | ارفع محتويات `dist/` عبر FTP |
| خادم VPS + Nginx | مدفوعة | يدوي (Let's Encrypt) | تحكّم كامل |
| جهاز في المتجر (شبكة محلية) | مجاني | ❌ | الكاميرا لن تعمل بلا HTTPS |

**مهم:** ماسح الباركود يحتاج HTTPS إلزامياً (قيد المتصفح، لا يمكن تجاوزه).
الاستضافة المحلية بلا شهادة تعطّل المسح — الإدخال اليدوي فقط.

### GitHub Pages — الخطوات
1. في `vite.config.js` أضف `base: '/R/'` (اسم المستودع).
2. انسخ `dist/index.html` إلى `dist/404.html` بعد البناء (لتعمل الروابط الداخلية).
3. Settings → Pages → Source: **GitHub Actions**.
4. مفاتيح Supabase تُضاف كـ **Repository secrets** لأن Vite يحقنها وقت البناء.
